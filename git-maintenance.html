Git 仓库维护

1. 为什么需要 .gitignore

.gitignore 用来告诉 Git 不要跟踪临时文件、编辑器配置、本地环境变量和构建产物。

本项目的 .gitignore 已忽略 .vscode/、日志文件和 .env 文件。

2. 检查仓库

git status
git remote -v
git branch -a
git log --oneline --graph --all

3. 查看和撤销修改

git diff                 # 查看尚未暂存的修改
git diff --staged        # 查看已经暂存的修改
git restore 文件名       # 丢弃尚未提交的修改
git restore --staged 文件名 # 从暂存区移除

注意：git restore 可能会丢失本地修改，执行前先确认文件内容。

4. 提交规范

提交信息要简短、清楚，并说明做了什么：

git commit -m "添加待办事项页面"
git commit -m "修复成绩判断逻辑"
git commit -m "更新 Git 学习文档"

动手任务

  1. 运行 git status，确认新出现的 .gitignore 和课程页面。
  2. 提交它们：git add . 和 git commit -m "完善仓库维护配置"。
  3. 推送到 GitHub：git push。
  4. 在 GitHub 仓库中确认能看到课程页面，但不会上传被忽略的文件。
